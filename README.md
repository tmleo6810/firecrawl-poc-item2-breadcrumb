# firecrawl-poc-item2-breadcrumb

[firecrawl-poc-mock](https://github.com/tmleo6810/firecrawl-poc-mock)（タグ `baseline-v1`）の複製 + `jobs.html` の追加。**検証 item2 専用**。

`jobs.html` と `assets/style.css` は [firecrawl-poc-item3-noise](https://github.com/tmleo6810/firecrawl-poc-item3-noise) の `baseline-v1` と**同一**（canonical URL の 1 行のみ差異）。両項目でベースラインを揃えるため意図的に複製している。

## これは何か

**Firecrawl の差分検知を検証するための、AI 生成モックサイト。**

実在するサービス・企業・求人ではない。掲載しているサービス名（ジョブモック / JobMock）・企業名・求人情報はすべて架空のダミーデータ。

実在の競合サイトは「いつ・何が変わったか」を制御できず検知結果の正解が作れないため、**変更のタイミングと内容を完全に制御できる実験台**として用意している。設計方針（決定論・デザイントークン集約・固定クラス名）の詳細はテンプレートリポジトリの README を参照。

- 公開 URL: https://tmleo6810.github.io/firecrawl-poc-item2-breadcrumb/
- **監視対象**: https://tmleo6810.github.io/firecrawl-poc-item2-breadcrumb/jobs.html

## item2 の検証内容

**既存要素の書き換え型・軽微な構造変更を検知できるか。**

item1（ブロック追加＝追加型）と異なり変更量が小さい。見どころは diff の表現（削除 + 追加として出るか）と、**judge が SEO 由来の軽微な変更を「意味あり」と扱うか**（実例ではデザイナーが報告価値ありと判断した）。

実例の出典: ジョブメドレーの求人検索結果画面でパンくずの構造が変更（2026-01-07 の定点観測投稿）。従前「ホーム > 保育士の求人 > 検索結果」→ 現在「ホーム > {都道府県} > {市区町村}の保育士求人」。SEO 目的の改修と推測されている。

| タグ | 状態 |
| --- | --- |
| `baseline-v1` | 変更前（パンくず: `ホーム > 求人を探す > 検索結果`） |
| `change` | パンくずを `ホーム > 東京都 > 東京都の求人一覧` に書き換えた状態 |

`change` で変えるのは**パンくずの文言とリンク構造のみ**。ページ見出し・検索条件表示・件数表示・求人カード・HTML の構造（タグ・クラス構成）は一切変えていない。

## `jobs.html` について

「検索条件: エリア = 東京都」で絞り込んだ想定の求人一覧ページ。テンプレの `index.html` からヘッダ・フッタ・`.job-card` マークアップを流用し、以下を追加している。

- パンくず（`.breadcrumb`）— **本項目の変更対象**
- ページ見出し「東京都の求人一覧」+ 検索条件表示（`.search-condition`）+ 件数表示（`.search-count`）
- 求人カード 6 枚（勤務地はすべて東京都内: 千代田区・新宿区・世田谷区・港区・杉並区・江東区）

パンくず・検索条件・件数表示のスタイルは `assets/style.css` の末尾に追加した。

## 運用上の注意

- **決定論性が検証の前提**。タイムスタンプ・乱数・外部読み込み・JavaScript を追加しないこと
- 検証期間中の変更は**「検証シナリオの適用」以外に行わない**（README の誤字修正であってもページ配信に影響し得る）
- **GitHub Pages は CDN キャッシュを持つ**（`Cache-Control: max-age=600` 目安）。デプロイ後は `curl` で新しい内容が配信されていることを確認してから Firecrawl 側の観測を始めること。ただし CDN のキャッシュは PoP 単位なので、自分の観測点での確認は Firecrawl 側の反映を保証しない
